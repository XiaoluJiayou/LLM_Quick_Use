# 项目整体优化计划与实施记录

基线：`5d1c969`；启动日期：2026-10-18。

## 范围与目标

基线包含 52 个 Python 文件、5 个 Notebook 和一个 Bash 入口。覆盖模型/数据下载、抽样与转换、文本生成与安全评测、CLIP、教学 LDM、图像生成评测、视频生成与评测，以及练习示例。Notebook 的代码单元纳入审阅；已有本地 `leetcode.py` 与 IDE 配置改动保留。

本轮交付以确认的运行错误、数据正确性和可重复执行为主，并建立后续优化的检查入口。真实模型效果、云服务权限、GPU 显存和吞吐需在对应运行环境实测，不用离线模拟结果代替。

## 分批实施顺序

1. **审计与规划**：读取全部源码和 Notebook，建立文件覆盖与问题清单。
2. **公共基础**：安装元数据、公共 JSON/JSONL/原子写/HTTP 工具、环境配置及检查工具。
3. **数据与文本流程**：下载 CLI、合并/抽样/转换、批量生成和裁判；修复 LDM 与 CLIP 的确认问题。
4. **图像与视频流程**：Notebook、抽帧、帧/视频判定、云服务入口及 vendor 输入和恢复验证。
5. **集成验收**：运行离线回归、复查改动、记录无法在本机执行的目标环境测试，更新项目说明。

任务可以按互不重叠的模块并行实施；合并验收按上述依赖顺序进行。

## 变更原则

- 不移动原目录，不删除示例和已跟踪的用户数据，不改变既有策略的法律或业务含义。
- API 凭据使用环境变量；不执行真实计费请求或批量下载权重。
- 保留必要的模型专属依赖环境，不把不兼容的 GPU 生态强塞到一个环境。
- 原有成功结果只有在输入、模型、参数等来源可确认时才续跑复用；损坏数据不当作空文件覆盖。
- 并发、量化、编译加速等性能升级以目标 GPU 的测量数据为依据，先提供可重复的基线。
